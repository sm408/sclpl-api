# UI Philosophy

SCLPLAPI UI work must support execution clarity, not overwhelm the runtime model.

## Principles

- workflow and request state must be legible
- editable structures should stay close to their runtime meaning
- advanced power should be available without forcing visual complexity
- the visual workflow builder comes after the runtime is solid

## UX priorities

- fast request authoring
- clear variable inspection
- understandable workflow execution feedback
- report/export visibility
